# Статус поставки 0.9.0

## Итог

`PARTIALLY_READY`

CLI, терминальное меню, XLSX/XLSM/XLSB readers, ZIP-манифест, аудит, ручная проверка и формирование карточки работают. Статус оставлен частичным, потому что в поставке используется совместимый шаблон, а не оригинальный пользовательский файл `карточка 24 остаток 30.07.26(2).xlsx`, и 1 270 решений на контрольном реальном запуске требуют ручной проверки.

## Исправления 0.9.0

1. Для источника `0907` детектор больше не доверяет одному заголовку остатка. Подозрительная пара, в которой количество совпадает со стоимостью, блокируется и заменяется проверенной тройкой `Количество → Стоимость за единицу → Общая стоимость` только при подтверждении формулами и сохранёнными значениями.
2. Shared formulas XLSX восстанавливаются относительно базовой ячейки. Формула вида `=<shared>` больше не теряется.
3. Короткие служебные значения `м`, `щ`, `пес`, `скрыть` и подобные больше не принимаются за шифр чертежа и не разрывают родительскую группу.
4. Валидатор блокирует:
   - одинаковые ненулевые количество и стоимость в массовом масштабе;
   - служебный маркер вместо шифра;
   - хвосты бинарного float в XML выходного XLSX.
5. Writer после безопасного сохранения атомарно заменяет только числовые XML-значения записанных quantity/cost-ячеек точным текстом `Decimal`. Обычные значения вроде `83108.99` больше не превращаются в `83108.99000000001`.
6. Пустой `manual_review.xlsx` не содержит некорректного `dataValidations count="0"` и проходит ZIP/XML/reopen-проверку.
7. Если в терминальном меню выбрать существующую папку вместо полного имени файла, приложение само добавляет `карточка_остатков.xlsx`.
8. Путь-выход, указывающий на каталог или не заканчивающийся на `.xlsx`, блокируется до длительной обработки.

## Ограничения

1. Поставляемый шаблон соответствует контракту `B2:X19`, но не является оригинальным пользовательским шаблоном.
2. Строки из `manual_review.xlsx` нельзя считать автоматически подтверждёнными.
3. Tiny-model backend вызывается только при явной конфигурации.
4. Стратегия `calculate_contract_minus_cumulative` остаётся выключенной по умолчанию; рабочая стратегия — `direct_remaining_columns`.
