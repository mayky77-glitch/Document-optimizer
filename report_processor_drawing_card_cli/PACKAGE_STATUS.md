# Статус поставки 0.9.2

## Итог

`PARTIALLY_READY`

CLI, терминальное меню, XLSX/XLSM/XLSB readers, ZIP-манифест, аудит,
интерактивная ручная проверка и формирование карточки работают.
`PARTIALLY_READY` означает, что пользователь явно разрешил выпуск при оставшихся
неблокирующих предупреждениях. Полностью строгий результат сохраняет статус
`OK` или блокируется.

## Интерактивная проверка

- Массово отклонить спорные строки и сформировать карточку без них.
- Одобрить все существующие предложения.
- Выбрать категорию для строк без предложения.
- Решить каждую строку отдельно.
- Учесть только количество или только стоимость.
- Пропустить строку либо отменить выпуск.
- Сохранить решения в `terminal_review_decisions.json`.
- Выполнить один повторный workflow с полным аудитом.

Обычный CLI остаётся неинтерактивным. Терминальный review включается только
флагом `--interactive-review`; встроенное меню добавляет его автоматически.

## Автоматические проверки

```text
PYTHONPATH=src python -m pytest -q
71 passed

PYTHONPATH=src python -m ruff check .
All checks passed

PYTHONPATH=src python -m ruff format --check src tests
55 files already formatted

PYTHONPATH=src python -m compileall -q src
OK
```

## Сквозная проверка

Контрольный ZIP обработан в отдельном временном каталоге:

```text
спорных строк до решения: 1270
действие: reject all
спорных строк после решения: 0
статус: PARTIALLY_READY
валидация результата: OK
исходный ZIP: SHA-256, размер и mtime не изменились
```

Реальные файлы, имена и финансовые значения в публичный Git-репозиторий не
включены.

## Ограничения

1. Массовое одобрение применяется только к строкам с предложенной категорией.
2. Для строк без предложения пользователь обязан выбрать категорию либо
   отклонить/пропустить строку.
3. Частичный выпуск не маскируется как полностью готовый: используется статус
   `PARTIALLY_READY`.
4. `FORMULA_WITHOUT_CACHED_VALUE` остаётся strict-блокером.
5. Tiny-model backend вызывается только при явной конфигурации.
