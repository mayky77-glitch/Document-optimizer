# report_processor — CLI-карточка остатков

Приложение командной строки для осторожного чтения строительных Excel-документов, поиска данных по шифрам чертежей, раздельного расчёта остатка количества и общей стоимости по восьми категориям и формирования проверяемой Excel-карточки.

## Главные свойства

- входы: `.xlsx`, `.xlsm`, `.xlsb`, папка, ZIP или несколько выбранных файлов;
- схема определяется по логическим заголовкам, а не по фиксированным буквам столбцов;
- формулы и сохранённые значения XLSX/XLSM читаются раздельно, формулы не пересчитываются;
- числа обрабатываются через `Decimal`, пустое значение не заменяется нулём;
- количество и стоимость классифицируются и агрегируются отдельно;
- неоднозначные источники, несовместимые единицы и спорные классификации не разрешаются молча;
- ZIP не распаковывается целиком;
- исходные файлы и шаблон не изменяются;
- каждый запуск создаёт полный аудит происхождения результата;
- поддерживаются `create`, `update`, `dry-run` и ручное подтверждение;
- подозрительное совпадение количества и стоимости блокирует результат;
- служебные значения в колонке шифра не разрывают родительскую группу;
- выходной XLSX проверяется на бинарные числовые хвосты и записывается с точными `Decimal`.

## Состав поставки

```text
config/drawing_card/        правила, подтверждённые примеры и примеры конфигурации
docs/                       ТЗ, аудит данных и руководство CLI
examples/                   демонстрационный вход и проверочный результат
templates/                  совместимый шаблон карточки
scripts/                    скрипты установки и демонстрационного запуска
src/report_processor/       исходный код приложения
tests/                      unit- и integration-тесты
```

> Важно: исходный пользовательский файл `карточка 24 остаток 30.07.26(2).xlsx` не был предоставлен в доступной среде. В поставку включён совместимый шаблон, соответствующий контракту B2:X19. Перед промышленным запуском рекомендуется передать оригинальный шаблон через `--template` и выполнить `analyze-drawing-template`.

## Быстрый старт

Требуется Python 3.12+.

### macOS / Linux

```bash
cd report_processor_drawing_card_cli
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
python run_cli.py --help
```

### Windows PowerShell

```powershell
cd report_processor_drawing_card_cli
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
python run_cli.py --help
```

Можно не устанавливать console script и запускать так:

```bash
PYTHONPATH=src python -m report_processor.cli --help
```

Полное руководство: [`docs/CLI_РУКОВОДСТВО.md`](docs/CLI_РУКОВОДСТВО.md).

## Безопасная рекомендуемая последовательность

1. `inspect-drawing-sources` — проверить файлы, объекты, листы и найденные столбцы.
2. `build-drawing-card --dry-run` — выполнить полный расчёт без создания итогового Excel.
3. Проверить `processing_summary.json`, `source_selections.json` и `manual_review.xlsx`.
4. При необходимости заполнить решения пользователя и импортировать их.
5. Запустить `build-drawing-card` без `--dry-run`.
6. Выполнить `validate-drawing-card`.

## Демонстрация

```bash
python run_cli.py build-drawing-card \
  --inputs examples/0906_demo_input.xlsx \
  --template templates/карточка_остатков_шаблон.xlsx \
  --output output/demo_result.xlsx \
  --mode create \
  --rag-mode off \
  --work-dir work
```

## Проверки разработчика

Скрипты `scripts/setup_mac_linux.sh` и `scripts/setup_windows.ps1` устанавливают
эти зависимости вместе с основными. После активации `.venv` запустите:

```bash
python -m compileall -q src tests
pytest
ruff check .
```

Фактические результаты поставки находятся в `PACKAGE_STATUS.md`.
