Работай внутри существующего Python-репозитория проекта обработки строительных Excel-документов.

Не создавай отдельный проект рядом и не переписывай рабочие компоненты с нуля.

Нужно полностью реализовать новую универсальную CLI-команду, которая:

1. Принимает один или несколько строительных Excel-документов.
2. Находит в них данные по каждому `Шифру чертежа`.
3. Для каждого шифра ищет восемь заданных категорий работ.
4. Отдельно рассчитывает:

   * остаток количества;
   * остаток общей стоимости.
5. Использует те же фильтры, нормализацию и правила включения, что и основной проект.
6. Для сложных наименований применяет:

   * детерминированный словарь;
   * поиск по подтверждённым примерам;
   * маленькую модель;
   * обязательное подтверждение сомнительных решений.
7. Создаёт или дополняет Excel-карточку по обновлённому шаблону:

   ```text
   card_template.xlsx
   ```
8. Работает из командной строки.
9. Сохраняет полный аудит происхождения каждого результата.

# 20. ЕДИНИЦЫ ИЗМЕРЕНИЯ

Единицу брать из строк, использованных для количества.

Ожидаемые единицы шаблона можно использовать только как проверочный справочник:

```text

Монтаж ТТ → м
Монтаж ЗРА ТТ → шт
Силовые сети → м
Слаботочные сети → м
```

Это не право молча заменять исходную единицу.

При конфликте:


В строгом режиме запись количества блокируется.

Стоимость разрешается считать отдельно, если её строки достоверны.

Нельзя суммировать:

```text

шт + м
м3 + т
```

Ноль является валидным количеством.

Пустое значение не равно нулю.

# 23. СЛОВАРЬ, RETRIEVAL И МАЛЕНЬКАЯ МОДЕЛЬ

# 38. ЗАПРЕТ НА ФАЙЛЫ-КОМБАЙНЫ

Строго запрещено:

* giant-regex;
* файл на 1 000+ строк;
* CLI с бизнес-логикой;
* writer с расчётами;
* matcher с чтением Excel;
* модельный клиент с агрегацией.

Ориентиры:

```text
функция: преимущественно до 30–50 строк
модуль: преимущественно до 200–300 строк
оркестратор: преимущественно до 150–250 строк
```

Это ориентиры, а не причина искусственно разрывать связную функцию.
