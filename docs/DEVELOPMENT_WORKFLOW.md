# Процесс разработки

1. Обновить `main` и зафиксировать базовый SHA.
2. Проверить архив, манифест и SHA каждого payload-файла.
3. Создать изолированную ветку `integration/<номер>-<название>`.
4. Использовать существующие модели, сериализацию, storage и CLI.
5. Добавить unit-, contract- и integration-тесты перехода предыдущего блока.
6. Выполнить `ruff check .`, полный `pytest` и доступные real-data gates.
7. Проверить SHA исходных пользовательских файлов до и после.
8. Обновить README и релевантную документацию фактическими результатами.
9. Создать один commit и draft Pull Request.

Реальные пользовательские данные не добавляются в Git. Для воспроизводимости
фиксируются только контрольные значения, статистика и SHA-256.
